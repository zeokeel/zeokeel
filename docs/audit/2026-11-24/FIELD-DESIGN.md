# 字段与说明文字的设计规范（举一反三）

> 范围：所有"标签 + 说明 + 控件"的表面——设置页 9 页、模型/连接器表单、composer、空态、状态徽标、审批卡。
> 目的：把第一轮/第二轮审计里 30+ 条"label 重复、help 同行、宽度随意、说明打架"收敛成**一条可执行的字段模型**。
> 样张：[`field-spec.png`](field-spec.png)（同目录，1440 宽，可直接给设计/前端看）。

---

## 0. 先回答"为什么不匹配"

现在的说明文字不是"写得不好"，而是**没有字段模型**——每个页面自己决定谁在上、谁在右、谁灰一点。表现有三种：

1. **职责混在一起**：标签（是什么）和帮助（为什么/怎么填）挤在同一行、同一字重，只靠 1px 的字号差（13 vs 12）和颜色区分。用户读到的是一句话被拆成两截 ——「语言 语言 界面语言；缺失时跟随浏览器。」。
2. **控件不表达值域**：枚举用自由文本、结构化数据用裸 JSON、数字没有单位、密钥用普通输入框。控件形状和"能填什么"脱钩，说明文字只好去补控件的缺口（"JSON 数组：{name, transport, command|url}。" 就是在替下拉框干活）。
3. **说明的位置和后果脱钩**：审批卡把"Esc 拒绝 · Cmd/Ctrl+Enter 允许"放在卡片底部 12px 灰字里（决定是否授权的信息放在最弱的位置），而禁用原因只藏在 placeholder 里（1.82:1）。

一句话：**说明文字要回答"这个控件要我怎么用"，而不是"这个控件叫什么"。**

## 1. 三条基准，一条结论

| 体系 | 它的硬规则 | 可借的点 |
|---|---|---|
| **antd 6 `Form`** | `label` 在上（vertical）或左（horizontal，`labelCol/wrapperCol`）；`extra` 在控件**下方** 12px 次要色；错误用 `validateStatus`+`help` **替换** `extra`；`tooltip` 是问号图标，只放低频解释 | 位置与字号是**组件属性**，不是每页手写；错误与帮助同槽位 |
| **DSH 设置行** | 标题 14 + 说明 12（secondary）两行文字在左，控件在右；数字用步进器（10–22，单位 px 跟随）；"更多字体设置"折叠低频项 | 行内**两段文字 + 一个控件**；低频项折叠，不摊平 |
| **GOV.UK / Material / Primer** | label + hint（hint 解释、不复述 label）；错误**紧贴字段上方**且红；一次只问一件事 | hint 与 label 的措辞分工；错误必须就近 |
| **macOS 设置 / Linear** | 左边标签、右边值；说明只在需要时出现；分组用 1px 线 + 12px 组标题 | 行高 44–56、组间距 24 的节奏 |

**结论**：三段式 —— **名称 / 理由 / 值**。三者不同行、不同字号、不同色阶；任意两者之间只有 4px 或 8px。

## 2. 字段解剖（数值即规范）

| 部位 | 规格 | 规则 |
|---|---|---|
| 标签 | 14 / 22 · 500 · `--zk-label-primary` | 名词短语；必填用红色 `*`，不写"（必填）" |
| 间距 | 4px | 标签→控件永远 4 |
| 控件 | 高 36（紧凑 28）· 圆角 8 · `--zk-border-l3` · 聚焦 `--zk-accent` + 2px `--zk-focus` 外环 | 高度只用两档；同屏不出现第三档 |
| 帮助 | 12 / 18 · 400 · `--zk-label-tertiary`，控件下 4px | 只写"留空/超出/失败会怎样"，**不复述标签** |
| 错误 | 12 / 18 · `--zk-danger-text` + 控件红边，**占据帮助的位置** | 错误与帮助不并存；失焦即校验 |
| 单位 | 12 · tertiary，控件内右侧 12px | 数字框右对齐 + `font-variant-numeric: tabular-nums` |
| 只读 | 14 · `--zk-label-primary`，无边框 | 配"复制"或"去修改"，不配输入框外观 |

**行与组**：字段↔字段 20px（紧凑 16）｜组↔组 24px + 1px 分割线｜组标题 12/18 · 500 · tertiary｜横向行（标签左、控件右）52px，标签下方带说明时 64px｜设置内容宽 ≤ 880（`SettingsWidth`）。

> 现状对照（实测）：标签重复两次；帮助与标签同行（13 vs 12）；数字框恒 90px；同屏 24/32/36 三档控件高度；字段间距 12/16/20/24 混用；只读"关于"页仍挂保存栏。

## 3. 控件 ↔ 说明文字 匹配矩阵

**先选出"值的形状"，再决定控件、宽度、说明位置、错误位置。** 这张表可以套到任何新产品上。

| 值的形状 | 控件 | 宽度 | 说明放哪 | 错误 / 校验 |
|---|---|---|---|---|
| 布尔 | 开关（行尾） | 44×24 | 标签下方 caption；不禁用 | 极少错；失败用行内提示 |
| 枚举 2–4 | 横排单选 | 内容宽 | **整组**下方一条 | 无 |
| 枚举 >4 | 下拉 | 240–320 | 下拉下方 | 无 |
| 短文本（id/名称） | 输入框 | 240–320 | 下方 caption；示例放 placeholder | 失焦即校验，错误替换 caption |
| URL / 路径 | 输入框 | 全宽 ≤640 | 下方说"留空=继承谁" | 实时红边 + 12px 文案 |
| 数字 + 单位 | 数字框 + 后缀 | 112–128 | 单位在框内；范围写 caption | 越界钳制并提示 |
| 密钥 | 密码框（可切换） | 全宽 | "留空=保留已存值" | 保存失败保留草稿 |
| 结构化（列表/映射） | **分步表单 / 键值编辑器** | 全宽 | 每条一行、行内编辑 | 逐条高亮，不整块报错 |
| 长文本 | textarea（可拉伸） | 全宽 | 下方 caption + 字数上限 | 超限即时 |
| 只读事实 | 文本 / `Descriptions` | 内容宽 | 不写说明；给动作 | — |

**当前反例**（都是"用错控件"）：MCP 服务器 / 禁用的工具 / Agent 预设 → 裸 JSON textarea；权限模式 / 主题 / 字号 → 自由文本或手打枚举；`上下文预算` → 90px 无单位；API Key → 普通输入框；`关于` → 只读却挂保存栏。

## 4. 输入框（composer）的说明文字：四层职责

输入区是"控件 + 说明"最密的表面，必须把四层分开，否则就会出现现在这种"同一屏两条 Esc 承诺"。

| 层 | 放什么 | 位置 | 规格 | 例子 |
|---|---|---|---|---|
| **placeholder** | 只放"能输入什么"的示例 | 文本区左上，与文字同起点 | `--zk-label-caption`，单行省略 | 给 ZeoKeel 发消息，`/` 命令，`@` 文件 |
| **长期 hint** | 键位、能力边界 | 卡片**下方**一行 | 12 / 18 · tertiary | Enter 发送 · Shift+Enter 换行 · `/` 命令 |
| **notice（状态说明）** | 为什么不能用 / 正在等什么 | 卡片**上方**一条（不是 placeholder） | 12 / 18 · secondary · 浅底 | 有 1 条审批等你处理 · 打开该会话 |
| **错误** | 发送失败、附件超限 | 卡片内紧贴出错处 | 12 · danger | 图片超过 10MB |

**权威对照（DSH `InputBar.module.css`，实测值）**：

- 卡片：`flex-direction: column; gap: 12px; padding-top: 8px; border-radius: 28px`；发丝描边 + 软阴影。
- 文本区在最上：`min-height 36`（hero 52），`padding: 4px 8px 0 14px`；placeholder 绝对定位在**同一 14px 左内距**。
- 工具条在文本**下方一行**：`attach(28) + Plan + Read-only` 左，`model + send(34)` 右，`gap 12`，`padding: 2px 8px 6px`；窄到 560px 时 gap 降 8、模型退化为图标。
- 统计行在卡片**下方** dock，预留 22px 高度，读数到达不改变卡片高度。
- 禁用原因写在卡片**上方** notice（12px secondary），不占用 placeholder。

**ZeoKeel 现状（实测）**：

| 维度 | DSH | ZeoKeel | 差 |
|---|---|---|---|
| 文本区高度 | 36（hero 52）→ 最大 336（14 行） | `minRows 2` → 空态 **96px**，最大 6 行（142px） | 空态高 2.7 倍、可写行数少一半 |
| 文本列起点 | 卡片左 + 14px（与 placeholder 同起点） | **x=537.7**（卡片左 288），且随控件增减在 505.8–567.3 漂移 **61.5px** | 视线要横跳 250px |
| 控件位置 | 文本**下方**一行，左 3 个 + 右 2 个 | 全部塞进左侧 `prefix`（228–253px），`+` 悬浮在 chips 上方 | 结构相反 |
| 控件尺寸 | `+` 28 · chips 28 · 发送 34 | 24 / 24 / 32 | 全小一档 |
| 卡片 | 圆角 28 · 宽 ≤952 · 0.5px 发丝边 | 圆角 12 · 宽 1128 · 1px 边 | 不在同一视觉语言 |
| 禁用原因 | 卡片上方 notice（12px secondary） | placeholder 灰字（对比度 1.82:1） | 用户不知道在等什么 |
| 统计行 | 卡片下方 dock，预占 22px | footer 内 38px，与 hint 混排 | 读数到达会跳高 |

**没有宽度约束的后果**：控件每加一个（权限→模型→思考），文本列就右移 60px 左右——所以"看起来飘"不是错觉，是布局在随状态变化。

**结论（直接可落地）**：`prefix` 只留 `+`；权限/模型/思考模式移入 `footer` 左区，发送键在右区；`minRows:1`；禁用原因升级为卡片上方 notice；hint 只写键位，不写状态；状态类文案全部上移到 notice。

## 5. 举一反三：三段式不止用于表单

同一条"名称 / 理由 / 值"可以解释其它屏的错位：

| 表面 | 名称（是什么） | 理由（为什么/下一步） | 值/动作 |
|---|---|---|---|
| 会话列表行 | 标题 | 时间 + 未读/运行态 | 悬停 `⋯`（重命名/删除） |
| 工具行 | 工具名 + 目标 | 耗时/状态（完成/失败/被拒） | 展开参数与输出 |
| 审批卡 | 工具名 + **影响对象**（URL/命令/路径） | 影响面一句话（会向外发请求） | 拒绝 / 仅此一次 / 始终允许 |
| 空态 | 这是什么 | 下一步做什么 | **一个**主操作 |
| 设置分组 | 组名（12px） | — | 组内若干行 |
| 状态徽标 | 语义文字（必填） | — | 语义 tint（不靠颜色单独表意） |
| 收件箱行 | 谁在等（会话名） | 影响面 | 与卡片**同一套**动作 |

现在这些表面的问题是同一个：**"理由"被塞进了"名称"的位置**（收件箱行标题 = 原始 JSON；工具行 = 协议枚举 `other`；审批卡 = `来自会话：… · 用户` 挤在右端）。

## 6. 迁移清单（按页，一句话/页）

| 页面 | 改什么 |
|---|---|
| 模型 | 目录行：名称 + `id · 地址 · 密钥状态 · 上下文` 两行；`设为默认` 变成行尾勾选；删除默认模型前必须要求"先选另一个默认"；弹窗改 `Form.Item`，主按钮不被折叠到视口外（或改抽屉） |
| 行为与限额 | 数字项统一 112px + 单位（秒/个/KiB）；`deniedGlobs` 从 JSON 改成"标签输入"；`agent.mode` 改成下拉或删除 |
| 外观 | 语言/主题用行内单选（整组一条 caption）；字号用步进器（10–22，单位 px）；热键改成"录制键位"控件，只读的托盘项直接标注"浏览器不生效"并禁用 |
| 通知 | 4 个开关改成"标签左、开关右"的行，删掉不成立的"分级"标题 |
| 网络与搜索 | 代理：地址 + 端口两行 + "测试"按钮；搜索端点 + API Key 两行；`直连列表` 改标签输入 |
| LSP | 服务器列表用可编辑表格（命令/参数/根目录），加"添加服务器"与"测试" |
| 归档 | 会话归档列表（标题/时间/恢复/删除），不要只有一个开关 |
| 数据与隐私 | 把 6 个裸 JSON 文本框拆成：禁用工具（可搜索多选）、禁用技能（多选）、技能目录（路径列表）、**MCP 服务器（表单：名称/传输/URL 或命令/参数/环境变量/超时 + 测试连接）**、禁用的服务器（多选）、禁用的工具（多选） |
| 关于 | 版本块用 `Descriptions`；发布说明是链接列表，不是输入框；只读页不渲染保存栏 |
| 收件箱 | 行 = 会话名 + 工具 + 目标 + 时间；动作与审批卡同源 |

## 7. 验收（可机器断言）

```js
// 一条字段必须满足的形状
label = 14/22/500, control = 36 or 28, help = 12/18/400 tertiary,
label→control = 4, control→help = 4, field→field = 20 (or 16), group→group = 24
// 断言：同一页出现的控件高度集合 ⊆ {28,36}；标签文本不出现在帮助文本里；
// 每个 <label for> 指向存在的控件 id；错误状态下 help 不在 DOM（被 error 替换）；
// 只读页没有 [data-testid=settings-save-button]
```

**一句话验收**：任一字段，把标签遮住——用户还能从帮助文字里知道"该填什么、留空会怎样、填错会怎样"吗？答不上来，说明帮助写成了标签的复读机。

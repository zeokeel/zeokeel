## 0. 结论

**最要命的一类问题不是"不好看"，而是"点了像成功、其实没发生"。** 这一轮找到三种固定模式：

1. **后端有、前端没接**：MCP 的 19 个扩展方法、会话管理的 4 个方法（重命名/删除/归档/fork）在协议里写着"延后"或被网关完全没实现，于是"添加连接器""管理会话"这类**用户每天要做的事根本没有入口**——唯一可写 MCP 的地方是「设置 → 数据与隐私」里 7 个裸 JSON 文本框。
2. **前端把"发出去了"当成"成功了"**：停止按钮只断本地流（后端继续跑，随后所有发送 409）；队列消息先 `remove` 再发（409 后消息凭空消失）；设置保存只写一行 `settings.set` 就提示"已保存"（非法 JSON、坏 baseURL、会话级失效一概放行）。
3. **状态与错误被吞**：连接器状态永远显示"空闲"（前端比 `'connected'`，后端给的是 `"已连接"`）；自动化 400 被渲染到弹窗**背后**；409 以英文 SDK 原文冒出来；"重启后生效"的设置项界面上**没有这句话**。

| B 模型配置 | 22 | 6 | 10 | 6 | 零校验 + 悬空默认 + 同一行两个控件 |

| E 设置接线 | 12（28 行表格） | 1 | 6 | 5 | 28 个设置项里 17 个不生效或需要重启而无提示 |

## 1. 方法

```bash
bash .cache/ui-audit/startN.sh <name> <port> <modelPort>   # 每个审计员一个独立数据目录
ZK_TOKEN=<token> ZK_BASE=http://127.0.0.1:<port> node <flow>.mjs
```

- **双证据**：`page.on('response')` 抓 `/api/**`；同时用 `WebSocket` 帧抓 JSON-RPC 方法名（本产品的写操作全走 WS，只抓 HTTP 会得出"没发请求"的错误结论）。
- **冷启动 A/B**：对"需要重启才生效"的设置项，用同一份 `settings.json` 起一个**并行实例**做对照（`data-wire2` @ :9899），避免被"端口静默协商/单实例锁"误导。
- **确定性输入**：每个失败用例至少两种取值（空/非法/超长/重复/跨字段矛盾），并对同一按钮点两次排除偶发。
- **对照**：DSH 各包的 `README.zh.md`（行为契约）+ `*.module.css`（尺寸）；antd 6 官方 API；主流产品（ChatGPT / Claude / Cursor / Copilot / Kimi）的既定范式。

### 4.1 输入框（`dsh-client-ui-conversation/src/client/skeleton/InputBar.module.css`）

| 维度 | DSH | ZeoKeel 现状 | 差距 |
|---|---|---|---|

### 4.3 MCP / 扩展（`dsh-mcp-manager`、`dsh-client-ui-plugin-manager`）

- DSH 的契约是"**配置变化即对账**"：新增挂载、移除卸载、`enabled:false` 卸载实例但保留条目、字段变化只重建那一个；坏条目在**写入处**被拒绝；状态是结构化联合类型（`connected | disabled | {failed, lastError}`）。
- ZeoKeel：配置只在一个 JSON textarea、无对账（需重启）、坏条目照存、状态是本地化中文字符串且与前端比较值不一致。

### 5.1 立刻（P0，按"最小可行修法"排序）

| # | 修什么 | 最小改动 | 验收 |
|---|---|---|---|
| 1 | **停止要真停** | `stopRun()` 先 `void cancelRun(sessionId)` 再断流 | 停止后服务端文本不再增长；紧接着发送不 409 |
| 2 | **队列不丢** | 发送成功后再 `prompts.remove`，失败回滚 + toast | 409 时队列项仍在 |
| 3 | **审批不跨会话** | `disabled` 只看 `a.sessionId === sessionId` | 会话 A 有待审批时 B 可正常输入 |
| 4 | **MCP 热重载** | `settings.set` 命中 `mcp.*` / `skills.dirs*` 时 `go mcpreload.Trigger(ctx)`（函数已存在）+ 推 `capabilities.delta`；在此之前把"已保存"改成"重启后生效" | 不改配置 → 刷新连接器页即出现并显示真实状态 |
| 5 | **连接器状态** | 读模型改 `{state, tools, lastError}`；UI 按 `state` 渲染 | 断开的服务器显示"连接失败 + 原因"，且可重试 |
| 6 | **连接器入口** | 能力页加「添加连接器」→ 表单（transport/url 或 command+args+env/超时）+「测试连接」；行内启停/删除 | 不碰 JSON 也能接一个 MCP server |
| 7 | **模型默认一致** | 删除默认前拦截（或同步改 `chat.model`）；`/api/models.defaultModel` 与 agent 用**同一派生函数**；目录空时发送报"未配置模型" | 删默认 → 有提示、不悬空；空目录发送有可读错误 |
| 8 | **模型校验** | 字段级 `rules`（URL/唯一 id/范围/交叉）+ 空列表不再报"损坏" | 坏值当场红边；`[]` 显示"还没有模型" |

## 0. 一页结论

1. **问题不是功能多，是「内部实现被当成了界面」**。默认路径上同时出现模型 ID、`tok/s`、缓存命中率、
   shell 名、工具函数名、MCP 握手、检查器、目标/团队、member-1…… 而小白只关心三件事：
   **能说话吗 / 它对我的东西做了什么 / 上次聊到哪**。
2. 一条简短问答的会话页常显约 **25–30 个非消息标签**，其中约一半小白默认不需要。
   最高收益的四项都在首屏/每次输入路径上：**状态条 6 指标、每条消息 usage、首页 tagline、模型下拉**。
3. **用户点名的终端问题不只是「多一个 bash 提示」，是 Windows 上真实坏掉了**：
   `modules/terminal/terminal.go` 的 shell 探测没有平台分支（`shellPreference = bash/sh/zsh/pwsh`），
   而同一产品的 agent 工具在 Windows 只用 pwsh（`toolkit/rebind.go`）。
   - 装了 Git Bash 的 Windows：显示「当前 bash」，`dir` 之类命令报 `bash: not found` + 退出码 127；
   - **原版 Windows（只有 cmd/powershell）**：头部字面显示 `shell`，运行任何命令报英文 `terminal: no shell available`。
   即：语言/选择器是表象，根因是 shell 解析与平台不一致。修它要连「减法 + 修 bug」一起做。
4. 设置中心实际 **18 页 / 5 组**（8 页默认收在「高级」，含「数据与隐私」）；展开高级后 1280×800 掉 2 页、
   1024×720 掉 4 页、900×600 需滚动；搜索只认页名（搜「字号」整块导航消失）。小白真正会用的只有 5 类事。
5. 右栏 8 个 pane 对小白是选择负担；其中「工具」pane 与「轨迹」tab 重复，「日志」是排障面；
   而「文件/改动」才是小白真正需要的。**团队 pane 不能删**（上一轮用户明确要求可见），改为「有团队才出现」。
6. 首启目前没有引导：`ui/welcome` 模块注册了但未进桌面装配；第一屏是开发者标语 + 默认模型
   `gpt-4o-mini` + 两条黄/红警告 + 三个平级按钮 + 侧栏「自动化/插件」。语言不跟随系统（默认 zh）。
7. 减法不是删能力：**默认层只回答三个问题，过程/计量降级为一行可展开，专业能力收进「高级」**。
   对标共识（Cursor/Replit/Lovable/Manus）就是三层：**一句人话的表层 → 一行可展开的过程 → 一个默认关闭的高级区**。

## 1. 目标态：三层信息结构（推荐）

```
L1 默认层（小白 95% 时间只看这层）
  · 一句人话的状态（"正在整理下载文件夹…"）
  · 对话正文 + 一行过程（"完成 8 步 · 1 分钟" ▸ 点开才是工具调用）
  · 输入区只有：输入框、附件、发送/停止（+ 当前安全档位一个词）
  · 首页：一句用途 + 大输入框 + 3 个示例 + 最近对话
L2 详情层（点一行才展开，不默认出现）
  · 工具调用的输入/输出、失败原因原文、diff 摘要
  · 轨迹（"它做了什么"）、文件/改动
  · 会话元信息（时间/模型/耗时/用量）
L3 高级层（默认关闭，一个开关/入口）
  · 右栏：日志、终端、工具、任务；插件页；自动化
  · 设置：MCP/LSP/网络/诊断/导入/快捷键/预设等
  · 模型 ID、Base URL、token 明细、缓存命中、权限模式全称
```

**一个原则**：高级能力只能有 **一个** 统一入口（设置里一个「显示高级功能」开关 + 命令面板），
不要每个页面各藏一处。

> 打分口径来自对标报告：`E = 理解成本 U × 出现频率 F`，`P = E − 4×(风险 R − 1)`。
> P 越高越应优先处理；P 为负的是「必须保留但要改写人话」。

## 3. 终端专项（用户点名，建议第一批就修）

**根因链**：
1. `modules/terminal/terminal.go:42` `shellPreference = {bash, sh, zsh, pwsh}`，无 `runtime.GOOS` 分支；
2. `Run` 固定 `shell -c`（`:255`），不区分 `-Command` / `/C`；
3. 同一产品 agent 工具在 Windows 只用 pwsh（`toolkit/rebind.go:38-51`）——两处口径不一致；
4. UI 端 `buildShellSelect` 即使只有一个 shell 也画「当前 + 下拉」，并显示 bash 名（`rightpanel/terminal.go:252-275`）；
5. 说明行「简单命令运行器（无 PTY / 持久 shell）」（`:237`）；路径显示绝对路径（`:158-164`）。

**修复方案（建议顺序）**：
1. **平台化 shell 解析**：Windows 依次 `pwsh` → `powershell` → `cmd`（`-NoProfile -Command` / `-Command` / `/C`）；
   POSIX 依次 `bash` → `sh` → `zsh`。与 toolkit 共用同一份解析，避免再次漂移。
2. **无 shell 不装坏**：空态说明 + 禁用输入（不再字面 `shell`、不再英文错误）。
3. **减法**：单选项不画选择器；多 shell 切换进 pane ⋯ 菜单；删 PTY 说明；路径显示文件夹名 + tooltip；
   失败主行人话 + 原文折叠。
4. **定位**：终端属于高级能力；默认不进右栏默认 pane 集合（见 C1），可从命令面板/高级模式进入。
5. Windows 真机验证（本环境 Linux，已用受限 PATH 模拟两种场景，需真机复核）。

## 5. 风险与约束

- **不能删的**：停止/中断、失败原因、审批与危险确认、权限档位、成本/上下文将满提示、文件改动 diff、
  团队/任务的存在性（上一轮明确要求可见）。减法只改「默认是否出现」与「措辞/层次」。
- **专业用户路径不能断**：高级模式/命令面板/设置必须能到达全部能力；快捷键不变。
- **实现坑**（调研已标注）：`ScreenLister.Screens()` 未过滤 `Visible`（`uiroot/runtime.go:236-243`），
  隐藏 screen 前必须先统一；改文案会撞 `home/i18n_test.go` 等既有断言；Windows 需真机复核。
- **不新增第二套壳**：减法=同一控件换文案/换位置/按需出现，不新建页面体系。
- 术语改名（工作区→项目文件夹等）涉及设置键/文案/测试面，建议一次性集中改并保留内部键名不变。

## 0. 结论摘要

整体完成度高：视觉语言已收敛、危险操作有确认、键盘路径基本成立、空态与错误提示明显优于修复前。
但从"人性化"（任务可发现、状态可预期、操作可撤销、反馈及时、术语可懂）看，仍有 **4 个 P1、13 个 P2、9 个 P3**，集中在 5 个主题：

1. **保存/生效语义不透明**：有的设置即时生效、有的按「保存」、有的按「应用」，且主操作在滚动末尾、关闭不提示未保存。
2. **可发现性依赖悬停/小图标**：消息操作、会话菜单、排队消息、工具卡摘要、插件失败重试。
3. **谨慎操作的默认值不够安全**：审批 Enter=允许；计划审阅输入反馈后 Enter 直接批准；「总是允许」范围是"本次运行"而非永久。
4. **开发者语言/原始数据暴露到用户界面**：会话 ID、Base URL、最大迭代、cron 原始串、英文技术描述、绝对路径。
5. **长页面/高频切换效率**：19 项设置导航无搜索；右栏 pane 两次点击；输入区 6 个芯片无分组。

## 2. 发现（按严重度）

### P1 · 阻碍级（会让用户做错/丢东西/被卡住）

#### H1. 设置弹窗：显式保存页的主操作在滚动末尾，关闭不提示未保存
- **现象**：「模型」「网络」「搜索」「外观」等页把主操作放在表单最后一行；打开页面时看不到 Save/Apply。外观页首屏底部只露出半截蓝色按钮。修改后点 X / Esc / 点背景关闭，没有任何「有未保存修改」提示；外观页又是"主题/语言即时生效、热键要点应用"的混合语义。
- **用户影响**：以为改完已生效、或关掉后才发现没保存；混合语义让人不知道哪些已变、哪些没变。这是设置类界面最典型的"不可预期"。
- **证据**：`internal/ui/settings/settings.go:1011`（模型页）、`:1074`（Save 在 Prompt 之后）、`:1185`（外观 Apply 在页面末尾）；`internal/uiroot/frame.go:602-622`（关闭只置 `open=false`，无 dirty 检查）；截图 `.cache/usability/shots/p2-model-settings.png`、`p2-appearance.png`（底部蓝色按钮被裁）。
- **design-guide**：§22「主操作必须清楚」、§15「设置使用熟悉的设置结构」、§26 final review（主操作是否显而易见）。
- **建议**：设置壳增加**固定底部动作条**（项目已有 `SlotSettingsPageFooter` 槽位）：页面贡献自己的主操作，滚动内容单独滚动；标题行显示「未保存」状态；关闭时若有 dirty → 确认框（保存/丢弃/取消）；热键的「应用」移到热键字段同组内，或与底部条共用一次保存。

#### H2. 模型页「测试连接」测试的是已保存配置，且抢了保存按钮的主操作
- **现象**：「连接检查」区里「测试连接」是 accent 主按钮且首屏可见；它读取的是已保存的 store/chat 配置（`modelCheckConfig`），而不是用户刚在输入框里改的草稿。用户改完 Base URL 后点测试，得到的是旧地址的连接结果；真正的「保存」在页面最底部、看不见。
- **用户影响**：按最显眼的按钮却得不到当前输入的反馈，容易被判为"配置错误/没生效"；也分不清先保存还是先测试。
- **证据**：`internal/ui/settings/model_check.go:63-78`（读取 `chat.Config()` 与 store 已保存值）、`:150-176`（`uikit.DialogFooter` 内 `Primary: true`）；`internal/ui/settings/settings.go:1074`（Save 在页面末尾）；截图 `p2-model-settings.png`。
- **design-guide**：§22 单一主操作、§15 熟悉的设置模式、§6/§16 组件服务信息（测试按钮不该冒充保存）。
- **建议**：测试使用**草稿值**（或先保存再测并明确提示）；测试按钮降为次按钮，旁边注明"测试将使用当前输入"；保存进固定底栏。

#### H3. 计划审阅：输入修改反馈后按 Enter = 批准，反馈不会被发送
- **现象**：计划弹窗有「告诉 agent 计划需要怎么改…」输入框，底部提示「Enter = 批准」。在输入框里敲完反馈按 Enter（最自然的提交动作），会直接批准计划；反馈文本没有提交给 agent。必须点「继续规划」才能发送反馈。
- **用户影响**：丢失输入 + 在"批准计划"这种不可逆决策上被误触；用户会以为 agent 已收到修改意见。
- **证据**：`internal/ui/interaction/interaction.go:334`（整窗 Enter=approve）、`:347-351`（反馈输入 `OnTextKey(enterTo(approve))`）、`:373`（固定提示语）；截图 `.cache/usability/shots/p2-plan.png`。
- **design-guide**：错误预防优先于提示；§15 熟悉模式（Enter 应提交当前表单，而不是跳过它）。
- **建议**：反馈非空时 Enter → `keepPlanning`；批准只在显式点「批准」（或焦点在批准按钮）时触发；底部提示按状态切换（"Enter = 继续规划（带反馈）"）。

#### H4. 审批浮层：默认 Enter=允许；「总是允许」实际只对本次运行生效
- **现象**：审批弹窗底部提示「Esc = 拒绝本次调用」，即默认 Enter=允许；对 `bash`/写文件这类危险工具也是同一个默认。另一个按钮叫「总是允许」，而实现里 `ApprovalAllowAlways` 的语义是 **"from now on for the run"**（本次运行内），不是永久。
- **用户影响**：误按 Enter 会直接放行一次工具执行；「总是允许」被理解为永久授权，之后同一工具不再询问，与用户预期不符。
- **证据**：`internal/ui/approval/approval.go:211`（`c.OnShortcut(0, ui.KeyEnter, resolveAs(ApprovalAllow))`）、`:240-252`（参数框/三按钮）、`internal/contracts/store.go:84`（注释：for the run）；截图 `.cache/usability/shots/p1-approval.png`。
- **design-guide**：危险操作要有安全默认与清晰后果说明；§15 熟悉交互（系统权限弹窗默认不聚焦"允许"）。
- **建议**：默认焦点放在「拒绝」或非危险按钮；Enter 仅在显式聚焦允许时生效（或对写/执行类工具二次确认）；「总是允许」改文案为「本次运行内始终允许」+ tooltip 说明；参数区对 `{}`/摘要型调用显示"无参数"而不是大空框。

### P2 · 明显不便（能用，但费解/费事/易错）

#### H5. 设置导航：19 个页面平铺滚动、无搜索/过滤；标题重复、快捷键页重复
- **现象**：设置左侧 6 组共 19 个页面（加分组标题）只能滚动查找；没有搜索框；每页又有一个「设置」小标题 + 页面大标题（两层标题）；「快捷键」页把「折叠/展开侧边栏」「打开命令面板」同时放进可编辑区和「全部快捷键」参考表，同一信息在页内出现两遍。
- **证据**：`internal/uiroot/frame.go:664-730`（分组导航）、`internal/ui/settings/settings.go:165-203`（快捷键页两个 Section）；截图 `p2-shortcuts.png`、`p2-appearance.png`。
- **design-guide**：§15 设置应可快速定位；§22 去掉重复层级。
- **建议**：导航顶部加搜索/过滤（原生 SearchField）；去掉「设置」小标题或把它做成面包屑；快捷键页把可编辑行合并进一个列表（编辑态行 + 只读行分组），删除「全部快捷键」中的重复项。

#### H6. 全局热键：要求用户输入 Electron 风格的原始 accelerator，且无键位捕获
- **现象**：外观页「全局热键」是普通文本框，占位符/当前值都是 `CmdOrCtrl+Shift+Space`；校验错误信息也教用户这个语法。快捷键页其它键位显示为 `Cmd/Ctrl + B`。没有"按下组合键捕获"的控件。
- **证据**：`internal/ui/settings/hotkey_settings.go:19-56`（TextInput + accelerator 校验）；截图 `p2-appearance.png` 底部。
- **design-guide**：熟悉模式、减少记忆负担；§6 用控件表达语义而不是让用户写语法。
- **建议**：做成录制型 key-capture（按组合键自动填入、Esc 取消、无效显示原因），显示格式与快捷键页统一；或在文本框旁提供「点击后按下组合键」按钮。

#### H7. 会话输入区工具条：控件多、术语混排、溢出按钮无标签
- **现象**：一行里同时有模型、权限（询问）、推理（默认）、模式（普通）、预设、斜杠、附件、发送 8 个控件；「询问/推理/默认/普通」对普通用户是内部术语；窗口变窄时其他控件收进 `»`，但 `»` 没有文字/图标语义（只有溢出）。
- **证据**：`internal/ui/session/view.go:1498-1660`（`buildComposerToolbar`）、`p1-chat.png`、`p2-rightpanel.png`（窄内容区时 `»`）。
- **design-guide**：§22 主次/降噪；§15 熟悉模式（聊天工具的模型设置通常收在一个菜单或设置里）。
- **建议 + 落地**：低频的推理/模式/预设已收进一个「会话设置」分组菜单；权限模式保留通俗说明 tooltip；`»` 溢出已彻底移除（动作行最多 4 个控件，窄窗折叠进带标签的会话菜单）；独立「/」「路径」按钮移除（键盘 `/` 与附件菜单保留同等能力）。

#### H8. 斜杠 / @ 菜单在布局流中推开内容，而不是锚定浮层
- **现象**：输入 `/` 或 `@` 时，菜单以面板形式插在 transcript 与 composer 之间，聊天内容被向上挤；菜单每行还有 chevron 装饰。关闭后内容再弹回。
- **证据**：`internal/ui/session/view.go:2030-2036`（`width=TranscriptWidth` 的 Column 直接放在布局流里）、`:2055`（每行 `ChevronRight`）；截图 `.cache/usability/drive/shots/slash-open.png`。
- **design-guide**：§15 熟悉交互（自动完成应为锚定 popover）；§12 视觉噪音（每行 chevron 无信息量）。
- **建议**：改为锚定在输入框上方的原生 Popover（或 overlay），不改变 transcript 布局；去掉每行 chevron，用选中底色表达高亮。

#### H9. 排队消息不可查看、不可取消
- **现象**：运行中发送会排队，但界面只有一个「已排队 N 条」徽章，内容只能靠 tooltip 逐行看；没有取消某条/清空队列的入口。
- **证据**：`internal/ui/session/view.go:1406-1416`（badge + Tooltip(strings.Join)）；无 queue 管理代码路径。
- **design-guide**：反馈应可操作；§22 次级信息可延后但不该不可见。
- **建议**：点 badge 弹 popover 列表（每条带删除/清空全部）；或在 composer 上方渲染可折叠的排队行。

#### H10. 右栏 Inspector「概览」把开发元数据当主内容
- **现象**：首屏依次是消息数、更新时间、**会话 ID**、模型、**Base URL**、API Key 状态、**上下文预算**、**最大迭代**。这些是诊断信息，不是用户日常要看的会话概览。
- **证据**：`internal/ui/rightpanel/view.go:210-240`；截图 `p2-rightpanel.png`。
- **design-guide**：§22 内容分级（Primary/Secondary/Tertiary）；§13 空态不必填满。
- **建议**：概览只留「标题/消息数/更新时间/运行状态/当前模型名」；ID、Base URL、迭代/预算收进「诊断」折叠或复制按钮，默认隐藏。

#### H11. 自动化任务不能编辑；调度显示原始字符串、缺人类可读解释
- **现象**：任务卡只有启用开关、立即运行、删除、历史；没有「编辑」。计划以等宽原始串显示：`*/30 * * * *`、`every 24h`；中文界面里出现英文 `every 24h`。创建表单的帮助文字要求用户理解 cron 子集或 `every <duration>`。运行摘要直接显示后端返回的英文/含 session id 的文本。
- **证据**：`internal/ui/automation/view.go:196`（`task.Schedule` 原样等宽显示）、`:320-338`（创建表单）、`:225-236`（动作区无编辑）；后端已有 `contracts.AutomationService.Update`（`contracts/automation.go:84-86`）但 UI 未接；截图 `p2-automation.png`、`p2-english-automation.png`。
- **design-guide**：§15 熟悉模式（计划任务应可编辑、调度应可读）；§22 主信息可懂。
- **建议**：加编辑（复用创建表单，预填 + Update）；调度框旁实时显示人类可读摘要（"每 30 分钟，下次 14:00"）；提供常用预设（每小时/每天/每周）减少手写；运行摘要若来自后端，考虑展示前做一行本地化/截断。

#### H12. 插件/MCP：失败恢复路径弱；工具开关"重启生效"提示弱；英文技术描述
- **现象**：MCP 行显示「连接失败 0 个工具」和「详情」，但重试按钮在页首「刷新」（离失败行远）；工具目录 70 项是一行英文长描述（developer docs 原文），只有开关；「工具开关在重启后生效」是节首提示，关闭项会显示「已禁用（重启生效）」，但重新启用时没有对应瞬时提示。
- **证据**：`internal/ui/plugins/view.go:94`（刷新）、`:164/343`（重启生效 badge）、`:186`（详情折叠）、`:278`（提示）；截图 `p2-plugins.png`。
- **design-guide**：错误恢复就近、反馈及时；§22 信息可懂（描述应可扫读）。
- **建议**：失败行内提供「重试连接」并把错误原因展开一行；工具描述截断+tooltip 全文，或本地化一句话摘要；开关变更后行内标「待重启」直到重启。

#### H13. Home 与会话输入区能力不一致：Home 的模型/模式只读
- **现象**：Home 输入区上方只显示「工作区 · 模型 · 模式」一行 muted 文本，不能点击切换；进入会话后才能用模型/模式菜单。Home 也没有"最近会话"入口（大块留白）。
- **证据**：`internal/ui/home/composer.go:257-276`（只读 chips 注释也承认 Home 无法操作）；截图 `p2-home.png`。
- **design-guide**：一致性；§22 主任务路径（开始对话前应能选模型）；§13 留白可接受，但应服务主任务。
- **建议**：让 Home 的模型/模式文本变为可点菜单（复用会话的菜单构建或 deep link 到设置模型页）；在 Home hero 下加 3 条最近会话（可关闭），减少回侧栏找。

#### H14. 破坏性操作没有撤销；连发 toast 会叠在一起挡内容
- **现象**：记忆删除/清空、任务删除、会话删除都是"确认框 → 删除"，没有 undo；同时多条通知会垂直堆叠，最多时可能压住 composer 上方内容（toast 已避开 composer，但会盖住 transcript 底部一行）。
- **证据**：`internal/ui/session/memory_tools.go:52-80`（AlertDialog 确认）、`internal/ui/automation/view.go:473-479`；`internal/ui/toasts/toasts.go`（堆叠 + inset 常量）；截图 `p2-toast.png`；截图 `p2-toast.png`。
- **design-guide**：可恢复性优于确认轰炸；反馈要可行动。
- **建议**：可逆操作（删除记忆/任务/会话）优先「删除 + toast 撤销（5s）」；不可逆操作保留确认；toast 同屏最多 2 条或合并为「+N 条通知」。

#### H15. 消息操作与工具卡信息可发现性弱
- **现象**：每条助手消息的动作入口是右下方一个很小的 `⋯`，离消息内容较远（截图里在工具卡下方右侧，容易被当成页面级操作）；复制/有帮助/没帮助默认隐藏。工具卡默认折叠「摘要」，右上角显示 `call-1` 这类内部 id；失败/短结果也要先展开才知道发生了什么。
- **证据**：`internal/ui/session/view.go:826-850`（⋯ 入口）、`internal/ui/toolcards/toolcards.go:100-110/237-241`（摘要折叠、call id）；截图 `p1-chat.png`、`p2-rightpanel.png`。
- **design-guide**：§22 信息层级（动作应邻近对象）；§15 熟悉的聊天工具操作；§9 不为装饰加徽章（call-1 是内部信息）。
- **建议**：动作行贴消息底部/悬浮于消息角落；复制常驻、反馈收进"⋯"；工具卡隐藏 call id，失败或极短结果默认展开摘要。

#### H16. 目标芯片菜单：「放弃目标」与「清除目标」并列、语义不清
- **现象**：目标 chip 弹出菜单含「暂停目标 / 完成目标 / 放弃目标 / 清除目标」，后两项都是红色、相邻，没有说明区别（放弃是否保留记录？清除是否同时取消？）。
- **证据**：`internal/ui/session/view.go:270-330`（goal menu 构建）+ 截图 `.cache/usability/drive/shots/overlay-goal-menu.png`。
- **design-guide**：危险操作后果要明确；§15 熟悉模式。
- **建议**：合并为「结束目标（保留记录）/ 删除目标记录」并加一句说明；或把"清除"移到二级菜单。

#### H17. 1024 宽窗口 + 右栏 drawer 会遮住 composer 右侧发送区
- **现象**：窄窗打开右栏时以 drawer 覆盖主内容，遮住 composer 右侧（发送按钮区域），用户要在"看右栏"和"发消息"之间先关抽屉。
- **证据**：`.cache/usability/shots/narrow/narrow-session-inspector.png`（右栏覆盖）；壳层检查器在 1092 以下按 drawer 渲染（`frame.go` 阈值）。
- **design-guide**：桌面结构应可共存；窄窗可接受 drawer，但输入区不应被挡住。
- **建议**：drawer 打开时给主内容加右 margin（而非覆盖），或把 composer 提到 drawer 上层；至少保证发送/停止按钮可点。

## 4. 做得好的地方（不用重做）

- 设置分组 + 原生 `ui.Switch`/可见标签 + 描述文字，开关与文案的关系清楚；危险操作 17 处原生 AlertDialog。
- 对话框统一 `DialogFooter`、Esc 提示、焦点归还；设置弹窗自适应 + 关闭 X + 重开滚动到当前页。
- 命令面板原生 SearchField/List（过滤、↑↓、Enter/Tab/Esc），/help 快捷键表会跟随自定义键位。
- 输入区 `ui.Toolbar` 保证窄窗发送/停止不被裁；右栏 pane 选择器 + 关闭 X + 行分隔；空态有下一步。
- toast 品牌化 viewport（不遮 composer、有级别图标/关闭/悬停暂停/读屏）；日期本地化；明暗/中英一致；无 emoji/Unicode 假图标，图标全部复用内部 icon set。
- design-guide 的"反 AI 味"检查基本通过：无卡片墙、无渐变/装饰图标、无每节边框、无仪表盘模板。

## 5. 建议修复顺序（投入产出比）

1. **设置保存语义**（H1+H2）：固定底栏 + dirty 提示 + 关闭确认；模型页测试连接改草稿并降级。用户每天都会碰到。
2. **两个误触决策**（H3+H4）：计划反馈 Enter 语义、审批安全默认与「总是允许」文案。风险最高。
3. **信息可发现性**（H5/H9/H15/H10）：设置搜索、队列管理、消息动作位置、概览降噪。改动小、感知强。
4. **常用工作流效率**（H11/H13/H26）：任务编辑、Home 可切模型、右栏快捷键。
5. **打磨**（P3）：术语/localization、路径/技术信息、撤销与 toast 堆叠。

- 独立审计（`.cache/real-test/settings-audit.md`）结论：不是选项太多，而是 20 个平级页面/分组排序问题；日常页与低频页混排、模型相关三页（模型/服务商/模型目录）、四种保存语义混用。

# 设置弹窗侧边栏 IA 评审（2026-11-16）

> 对象：设置弹窗左侧导航（`internal/uiroot/frame.go` 的 `settingsNavColumn`，现 224 DIP 宽）。
> 页面现由 `internal/ui/settings` 的 10 个页面组成（原 16 页 + `internal/ui/about` 1 页已按本报告合并）。
> 结论先行：**17 个一级导航项 → 10 个 / 5 组**；功能不删，只把「不是独立设置」的项
> 合并/下沉。核心问题不是样式，是**信息架构**：导航太长、分组混杂、两个「能力」重名。
>
> **状态（2026-11-16）**：已按本报告实施 10 页 / 5 组；旧页面 ID 保留 host alias 深链；
> 「预设」页按用户后续要求删除（数据键保留）；权限模式移到输入框工具栏的权限按钮（按钮文案即当前权限）。

## 1. 当前事实

- 面板：`design.SettingsWidth/Height = 820 × 760`；导航列固定 **200 DIP**；搜索框 + 分隔线在顶部，其余滚动。
- 分组：6 组、17 页（`settingsSectionRank`：常用 12 / 外观 30 / 集成 50 / 数据与通知默认 70 / 高级 80 / 关于 90）。
- 分组明细：

| 分组 | 页面 | 页面性质 |
|---|---|---|
| 常用 | 模型、行为、预设 | 配置 + 管理列表 |
| 外观与语言 | 外观、快捷键 | 配置 + 键盘参考（含 2 个可编辑快捷键） |
| 集成 | 搜索、网络、能力（限额）、LSP | 配置，但「能力（限额）」与分组语义不符 |
| 数据与通知 | 通知、记忆、归档、数据与隐私、导入、更新 | 6 项混杂：偏好 / 内容管理 / 一次性迁移 / 更新动作 |
| 高级 | 诊断 | 只读运行时信息，不是设置 |
| 关于 | 关于 | 版本/构建信息 |

**证据**

- 中文 1512×944 快照（`.cache/ui-conformance/p2-model-settings.png`）里导航只显示到「更新」，
  「高级」「关于」在折叠区下方，需要滚动才能看到；英文快照（`p2-english-settings.png`）因为
  `Appearance & langu...` 被截断，反而正好塞下——说明高度处在临界点。
- 只有「高级」组默认折叠（`frame.go:1721`、`frame.go:1920`），其余 16 项常显。
- 搜索命中项只在 4 个页面有声明的 `SearchItems`（模型 / 外观 / 通知 / 行为，`settings.go:761/814/900/912`）；
  其余 13 页只能命中页面级关键词，搜索「代理」「超时」「并发」只会打开页面顶部，不会定位到字段。

## 2. 非必要作为「一级导航项」的项

> 不是建议删功能，而是这些项不需要独占一个侧栏目的地。

| 项 | 现状 | 为什么非必要 | 建议 |
|---|---|---|---|
| 诊断 | 只读运行时/构建/设置键信息 | 不是设置；与「关于」的构建信息重复 | 并入「关于 → 诊断信息」折叠区 |
| 更新 | 检查/下载/安装、更新状态 | 是动作/状态，不是偏好；低频 | 并入「关于 → 版本与更新」，更新可用时在「关于」导航项上点一个状态点 |
| 导入 | DSH 数据一次性迁移 | 一次性任务，长期占一级导航 | 并入「数据与隐私」页内「从 DSH 导入」区块；或仅在检测到 DSH 数据时 `Visible` |
| 快捷键 | 2 个可编辑快捷键 + 只读键位表 | 键盘属于外观/输入；独立页低频 | 并入「外观」页的「键盘」区块（可折叠） |
| 搜索 | 搜索后端 endpoint/API Key | 与「网络」同属联网能力，两个半页 | 与「网络」合并为「网络与搜索」 |
| 能力（限额） | 委派并发、Shell 超时/输出上限、并行工具 | 技术限额；与「行为」的权限/运行偏好重叠；且与侧栏顶级「能力」页重名 | 并入「行为」并改名「行为与限额」 |
| 归档 | 归档会话列表/恢复/删除 | 内容管理不是设置；会话的归档入口更适合侧栏 | 优先进「数据」组；P2 可迁到会话侧栏的「已归档」 |

**不建议动的**：模型（核心）、行为（核心，合并限额后更强）、外观、预设、通知、记忆、
数据与隐私、LSP（保留在「连接」组，面向开发者）、关于。

## 3. 建议的目标 IA（10–11 项 / 5 组）

| 组 | 页面 | 页内结构 |
|---|---|---|
| 常用 | 模型 | 模型列表 / 提示词与运行参数（现状已分区） |
| 常用 | 行为与限额 | 默认权限、工作步骤、字号、指令文件；**新增**「委派/Shell/并行工具」区块 |
| 常用 | 预设 | 预设列表 + 新增预设 |
| 界面与通知 | 外观 | 主题、语言、桌面集成、全局热键；**并入**「键盘快捷键」 |
| 界面与通知 | 通知 | 气泡、系统通知 |
| 连接 | 网络与搜索 | 代理 + 搜索后端/API Key（两个 Section） |
| 连接 | LSP | 语言服务器 |
| 数据 | 记忆 | 记忆列表/整理策略 |
| 数据 | 数据与隐私 | 数据目录、会话清理、**DSH 导入** |
| 关于 | 关于 | 版本/构建/许可 + **更新** + **诊断** |
| （数据，可选） | 归档 | 若暂不迁到侧栏，保留为「数据」组第三项（总数 11） |

这样：**分组 6 → 5，一级项 17 → 10（含归档 11）**；中文 760 高面板无需滚动即可看全，
英文不会出现 `Appearance & langu...` 截断（组名也建议从「外观与语言」改为「界面与通知」）。

## 4. 需要增强的点

### P0（影响理解，优先做）

1. **解决「能力」重名**：侧栏顶级页已叫「能力」（技能/连接器），设置里还有一个「能力」限额页。
   建议设置页改「行为与限额」/「权限与限额」，搜索别名补「并发/限额/超时」。
2. **导航宽度与截断**：200 DIP 在英文下截断分组名。建议 220–224 DIP，或把组名缩短为
   「界面」「连接」「数据」「关于」；同时把「数据与通知」拆成「数据」「通知」。
3. **移除「高级」折叠层**：合并「诊断」后它只剩一个不可见入口，收益为负；直接并入「关于」。
4. **搜索锚点补齐**：给网络（代理）、搜索（端点/API Key）、能力（并发/超时）、记忆（整理策略）、
   数据与隐私（数据目录/清理）声明 `SearchItems + Reveal`，让搜索直达字段而不是页面顶部。
5. **导航脏标记**：有未保存草稿的页面在导航行显示小圆点/「未保存」无障碍名（当前只有弹窗标题行
   显示一个全局「未保存」徽章），避免用户不知道哪一页有草稿。

### P1（体验提升）

6. **搜索反馈**：查询变化时在导航顶部显示「N 个匹配」；无结果时给建议（模型/主题/通知）；
   `Cmd/Ctrl+F` 聚焦搜索；`Esc` 第一次清空搜索、第二次才关闭设置（需与 SearchField 现有 Esc 语义对齐）。
7. **分组排序显式化**：`settingsSectionRank` 对「数据与通知」没有显式 rank（默认 70），建议写入
   显式值并删除未知分组兜底，避免以后新组插错位置。
8. **页面深链兼容**：合并/改名后为旧 ID 保留 alias（`shortcuts→appearance#keyboard`、
   `search→network#search`、`capabilities→behavior#limits`、`import→data-privacy#import`、
   `update/diagnostics→about#...`），否则 palette `goto settings/xxx`、`OpenSettingsPage`、
   文档和用户习惯都会断。
9. **关于页成为「版本/更新/诊断」中枢**：版本、检查更新、更新说明、诊断信息、许可；
   「有可用更新」时在「关于」导航项显示状态点，而不是再占一个「更新」页。
10. **记忆/归档的归属**：记忆是内容管理、归档是会话管理，放在「数据」组比和「通知/更新」混排合理；
    若后续做侧栏「已归档」筛选，再把归档从设置移出。

### P2（可选，先不做）

11. **页面导航图标**：不建议给每个设置项加图标；分组名和页面名已经足够。只在「更新可用」「有未保存」
    等状态上使用点状指示。
12. **记住上次访问页**：当前打开默认第一页（模型）；可记住上次页，但不要影响搜索/深链。
13. **列表计数徽章**（预设/记忆/归档 N 项）：只在有明确动作价值时加，避免把导航变成 dashboard。
14. **窄窗适配**：设置面板最小 640；导航固定 200 在窄窗下内容区 440，仍可接受；若再压缩，
    考虑把导航收成 168 DIP 或分组折叠，而不是隐藏搜索。

## 5. 实施顺序（如果按此报告做）

1. 先做 P0 的「改名 + 合并网络/搜索 + 更新/诊断并入关于 + 去掉高级组 + 导航宽度」，
   一次性把 17 项降到 10–11 项；同步更新 `ui-drive` 设置页清单（当前 17 页）、快照与文档。
2. 再补搜索锚点、脏标记、匹配计数与快捷键。
3. 最后评估归档迁侧栏、上次页记忆等 P2 项。
4. 改合并页时保留旧 page ID 的 alias，并加帧测试：旧深链打开正确页、搜索命中正确锚点、
   关闭/重开无脏草稿残留。
